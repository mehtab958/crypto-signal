# crypto-signal

A 24/7 crypto trading bot with its own strategy library, a research pipeline that tests every
strategy honestly (in-sample / out-of-sample / walk-forward), and paper + live execution through
[ccxt](https://github.com/ccxt/ccxt) (Binance, Bybit, Kraken, OKX, Coinbase, ...).

> **Risk warning.** Backtests are not promises. Everything here is long-only spot trading with no
> leverage, but you can still lose money. Run in `paper` mode first, then go live with money you
> can afford to lose.

## Results (BTC/USD, costs included)

Full report with charts: [`results/RESULTS.md`](results/RESULTS.md).

Strategies and parameters were chosen using **only 2017–2022**. 2023 → Oct 2026 was never looked
at while choosing, so it shows how the bot would have done on unseen data. The walk-forward test
re-runs the whole selection every January using only the past and trades the next year blind.

| test | CAGR | Sharpe | Max drawdown |
|---|---|---|---|
| Walk-forward 2019–2026, **portfolio** | 33.1% | **1.16** | **-37.5%** |
| Walk-forward 2019–2026, buy & hold | 47.5% | 0.95 | -77.1% |
| Out-of-sample 2023–2026, **portfolio** | 19.0% | 0.87 | **-26.9%** |
| Out-of-sample 2023–2026, buy & hold | 49.6% | 1.11 | -53.6% |
| In-sample 2017–2022, portfolio | 77.4% | 1.76 | -36.1% |

What this means:

* The portfolio's edge is **risk control**. It lost 19% in 2018 and 22% in 2022, when BTC fell
  73% and 64%. Its worst drawdown is about half of buy & hold's, and its walk-forward Sharpe is
  higher.
* In strong bull runs (2017, 2020, 2023–24) it lags buy & hold, because trend filters enter late
  and the volatility targeting holds smaller positions.
* Out-of-sample results are well below in-sample ones. That gap is normal and is why the
  walk-forward number is the one to plan around.

### Every strategy tested

| strategy | idea | verdict |
|---|---|---|
| `ema_trend` | fast/slow EMA cross + ADX trend filter + ATR trailing stop | ✅ selected (4h, 1d) |
| `donchian_breakout` | close above N-bar high, exit below M-bar low / ATR stop | ✅ selected (4h, 1d), best single strategy OOS |
| `vol_momentum` | multi-horizon time-series momentum sized by volatility targeting | ✅ selected (4h, 1d), most consistent |
| `bb_squeeze` | Bollinger-band squeeze then upside breakout | ⚠️ selected on 4h; failed out-of-sample (−5% CAGR). Rejected on 1d |
| `rsi_dip` | buy oversold RSI dips inside an uptrend | ❌ rejected: no parameter set beat buy & hold in-sample |
| any strategy on **1h** | – | ❌ fees (0.15%/side) eat the edge |

The portfolio averages the 7 selected strategy×timeframe members. Each member outputs a
position from 0 to 1, so the bot often holds a partial position.

## How it works

```
crypto_signal/
  indicators.py      EMA, ATR, ADX, RSI, Bollinger, Donchian, realised vol (all causal)
  strategies/        strategy library (each maps candles -> target position 0..1)
  backtest.py        bar backtester: next-bar execution, fees + slippage, full stats
  research.py        grid search, robust parameter pick, IS/OOS selection, walk-forward
  portfolio.py       blends members across timeframes (aligned on candle close times)
  report.py          writes results/RESULTS.md + equity/drawdown charts
  bot.py             24/7 scanner + paper/live trader with risk controls
config/portfolio.json   the selected strategies + parameters (generated by research.py)
data/                BTC/USD 1h/4h/1d candles 2016 → Oct 2026 (Bitstamp)
```

Anti-overfitting rules in the research:

* Parameters are chosen by the **median Sharpe of the parameter and its grid neighbours**, not
  the single best result, so a lucky spike in the grid is skipped.
* A strategy is used only if it beats buy & hold in-sample **and** ≥75% of its parameter grid
  does too.
* Signals use closed candles only and are applied from the next bar. Tests check that no
  strategy looks ahead, and that the live bot's signal matches the backtest exactly.

## Usage

```bash
pip install -r requirements.txt
pytest                                           # 13 tests

python -m crypto_signal.research --walk-forward  # re-test every strategy, rewrite config/portfolio.json
python -m crypto_signal.report --walk-forward    # regenerate results/RESULTS.md + charts

cp config/bot.example.yaml config/bot.yaml       # edit exchange, symbols, risk limits
python -m crypto_signal.bot scan                 # current signal for every symbol
python -m crypto_signal.bot run                  # paper trade 24/7 (default mode: paper)
```

### Running 24/7

```bash
docker compose up -d --build    # restarts automatically after crashes and reboots
docker compose logs -f
```

Or use any process manager (systemd, pm2, `tmux`) with `python -m crypto_signal.bot run`.
The bot wakes up after every 4h candle closes. It saves its state to `state/bot_state.json`,
so it can be restarted at any time.

### Going live

1. Paper trade for a few weeks and check `bot.log` and `state/bot_state.json`.
2. Optionally set `sandbox: true` to use the exchange's testnet.
3. Create an API key with **trading only, no withdrawals**. Put it in `.env` as
   `EXCHANGE_API_KEY=...` and `EXCHANGE_API_SECRET=...` (and `EXCHANGE_API_PASSWORD` for OKX
   etc.).
4. Set `mode: live`. In live mode the bot uses your whole quote balance, split equally across
   `symbols`. Use a sub-account holding only the money the bot should trade.

Risk controls: `max_drawdown` kill switch (sells everything and stops trading; to resume, delete
`halted` from the state file), `min_order_value`, a `rebalance_threshold` that avoids
fee-burning small trades, and exponential backoff on exchange or network errors.

### Scanning more coins

`symbols` can list any number of pairs, for example `[BTC/USDT, ETH/USDT, SOL/USDT]`.
Parameters were researched on BTC only, so paper trade any other coin before going live with it.
